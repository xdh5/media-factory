# Agent 集成验证记录

验证日期：2026-10-20。

## 环境与方法

使用 Windows Python 3.12.10、LangGraph 1.2.16、SQLite 检查点扩展 3.1.2 和项目现有依赖，在 `.venv-agent` 中执行。没有新增单元测试。

临时集成脚本位于被忽略的 `cache/agent-verification/integration_check.py`。脚本启动本地 OpenAI 兼容 HTTP 服务，通过独立 Python 进程运行实际 Agent CLI，连接真实的项目 stdio MCP，检查 SQLite 检查点与工具回执。每次审批、状态查询和恢复均使用新的 CLI 进程，验证进程退出后恢复。

验证只调用本地配置查询、提示词生成和不存在任务的查询；实际发布工具在审批处拒绝。没有生产视频、发布视频或修改远端业务数据。

## 通过的场景

- 四个现有 MCP 服务启动、动态发现共 98 个工具并读取四份服务说明；原 GitHub 工作流客户端导入保持兼容。
- 自然语言任务经 HTTP 工具调用完成 MCP 执行，工具结果进入后续 LLM 请求。
- 单次返回多个工具调用，顺序执行；人工补充信息后跨进程继续，前序查询不重复执行。
- 审批通过后执行，拒绝后不执行；相同副作用参数换用新的调用 ID 也不重复执行。
- 已保存成功回执而图尚未推进时，恢复直接复用回执。
- 模拟副作用回执不确定，恢复暂停核对；提交实际结果后继续，明确授权重试后只执行一次。
- 将工具超时设为极短值，实际触发超时，任务进入回执核对，避免自动重复副作用。
- 只读工具错误有限重试，错误回传 LLM；工具参数不符合 JSON Schema 时不执行工具。
- 模型接口首次返回 HTTP 503 后有限重试成功。
- 最大步骤达到上限后停止；极短运行超时仍保留初始检查点，可跨进程恢复完成。
- 暂停后用空 JSON 确认恢复；运行期间由另一个进程请求暂停，在下一操作边界暂停。
- 同一任务并行恢复被文件锁拒绝，状态查询和暂停请求仍可并行处理。
- 真实统一发布工具在调用前进入审批，拒绝后没有启动发布。

最终完整集成脚本通过；运行中暂停与并发锁另行通过跨进程集成验证。

另使用项目现有 `DASHSCOPE_API_KEY_FINANCE`，设置 `DASHSCOPE_BUSINESS_LINE=finance` 后连接真实上游模型。任务限定为只调用一次 `finance_get_production_config` 并概括素材方案，实际完成 LLM 决策 → MCP 工具调用 → LLM 总结，共三步，状态为 `completed`。回执位于被忽略的 `cache/agent-verification/live-model.sqlite`。

## 其他检查

`compileall`、`pip check` 和 `git diff --check` 通过。

Docker 服务未启动，因此未执行镜像构建。本地 HTTP 服务用于可控的异常及恢复场景，真实上游模型用于 Tool Calling 正常流程验证。视频生产和实际发布不在本次验收范围内。

原 MCP 本地后台线程任务仍受其子进程生命周期限制。Agent 的检查点恢复不保证媒体计算线程在进程退出后继续运行。对外部操作执行成功但回执未保存的窗口，采用人工核对，不能保证跨系统严格一次执行。
