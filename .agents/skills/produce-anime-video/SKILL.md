# 生产动漫视频

## 作者主页找剧

用户要求按动漫制作发布流程执行时，先调用 `anime_get_production_config` 自动取得已有动漫账号组，唯一可用组不重复询问。仅制作不自动发布。

用户同时要求发布到 YouTube 时，只执行本节的发现、匹配和必要取证步骤，不执行第 6 步本地生产。改用 `publish-anime-youtube` 技能中的 `anime_start_prepare_execution`，由 GitHub Action 全量下载、拼接和上传。片段取证仅远程截取短片段，不下载完整来源。

用户提供作者主页和作品名，即授权自主查找、下载与本地拼接，无需逐条让用户选链接。当前主页扫描复用 media-collector，仅支持抖音；其他平台主页不能冒充支持。

1. `anime_start_discover(profile_url, series_name, limit=300)`，轮询 `anime_poll_task` 到完成，取得 `discovery_path` 和作品列表。根据标题、描述、明确集数、发布时间和时长匹配作品，包括别名。必要时扩大扫描到 1000 条；达到上限需报告范围，不能声称已扫描整个主页。
2. 明确集数优先，发布时间辅助，忽略置顶展示顺序。识别补发、重发和同名不同版本。没有集数时结合描述和发布先后判断；证据不足先继续取证，仍不明确再问用户。
3. 优先找现成合集，文字中的全集、集数范围和时长综合判断。长视频仅为疑似合集，不能单凭时长认定。
4. 标题描述不能判断时，调用 `anime_start_inspect(discovery_path, work_ids, window_starts)`，每次最多八条、每条最多四个 45 秒口播片段；默认从第 5 秒开始。比较疑似合集与对应首集的前几句有效口播，必要时更换起点跳过公共片头，并核对中后段或结尾。开头相同只证明首集存在，不能证明全集完整。只取必要片段，不默认全量转写。
5. **封面识别必须最后兜底**：先完成对应作品的片段取证；标题描述、集序、时长和片段仍不足时，再调用同一取证工具，传 `window_starts=[]` 和具体 `cover_reason`。工具复用已有千问视觉识别封面文字，不默认批量识别封面。语音转写使用已有 Groq 服务，封面使用千问，会产生对应服务用量；失败时报告配置或服务错误，不伪造识别结果。
6. 确定来源后调用 `anime_start_compile_series(discovery_path, work_ids, selection_reason)`，ID 顺序由宿主判断。原因记录匹配依据、排序、合集覆盖、去重、缺集和完结状态。完整合集只选合集一条，直接下载交付原文件，不切分。部分合集可与未覆盖分集组合，例如 1—7 集合集加 8—12 集；禁止把 1—7 合集再和 1—7 分集重复拼入。合集之间重叠且无法选出不重叠来源时先报告，不盲目拼接。
7. 缺集或仅更新到某集时明确报告，不声称全集完结。所有 start 均轮询到完成，不重复启动。取证短片段不代替完整生产来源。成功后交付路径与原文案。

## 别名与缺集复核

作品归属由宿主 LLM 综合判断，关键词和正则只用于整理候选，不能作为最终排除依据。先浏览本次扫描的全部精简标题；输出过长时分批读取或按发布时间整理，不能把输出截断当作已读完。留意人物姓名替代称谓、改名、简称、同音字、错别字，以及只有集号或剧情的标题。

发现集号断档时，回到完整列表查找对应集号及相邻发布时间的其他作品，比较人物名、剧情、时长和后续是否换回原名；不要仅在最初关键词命中的子集中查缺集。例如“林老太重生记”中间改叫“林清如重生记”，且集号与时间衔接，应主动纳入同剧候选。这个例子说明判断方法，不是固定别名字典；同集号或时间接近不能单独证明同剧。

重复集号可能是标题误写、补发或不同版本，不能直接删除后一条，也不能直接将其改成缺失集号。分别核对来源。文字证据不足时，只对疑似别名、重复号及必要的相邻集调用 `anime_start_inspect`，先取一个短片段核对人物与剧情衔接，再按需补取；不默认批量转写或全量下载。

报告前区分已确认同剧、疑似同剧待取证、当前扫描未找到三种情况。尚有合理候选时只能说“集号未匹配，待核对”，不能直接宣称缺集或全集。选片原因记录采用的别名及证据、重复号处理和仍未找到的集号；仅在必要取证后仍有歧义时请用户判断。用户要求控制耗时或 token 时，扩大取证前先汇报候选数量和预计工作范围。

## 已排序视频链接

用户给出一条或多条抖音、快手或其他视频分享链接，并要求按这个顺序拼在一起时使用本技能。用户给出链接即表示授权下载和本地拼接，无需再次确认，也不要询问计划发布日期。

只通过 `anime` MCP 完成：

1. 调用 `anime_start_compile`。`share_texts` 是数组，每个元素一条分享口令或链接，顺序必须与用户给出的顺序一致，不要排序或去重。
2. 用返回的 `task_path` 调用 `anime_poll_task`，直到 `done=true`。未完成时不要再次 start。拼接可能很久，两次轮询至少间隔 5 秒。
3. 成功后列出每一段的本地路径、标题、描述和话题。这些文案必须原样展示，禁止润色、翻译、合并改写或自行补充话题。

规则：

- 按三小时估算段数，选择最接近均分目标的完整剧集边界，禁止切断剧集；保全剧集优先，允许单段超过三小时。
- 产物在 `cache/output/anime/run-*/`，旁路的 `.txt` 和 `.json` 是同一份解析文案。
- 本 MCP 不发布。用户没要求发布时，到此结束。
- 用户要求把链接里的长视频拆成多集发布到 YouTube 时，不在这里本地拼接，改用 `publish-anime-split-youtube` 技能。

如果 MCP 未连接、进程退出或调用失败，报告具体错误并停止，不得绕过 MCP 自行下载或拼接。
