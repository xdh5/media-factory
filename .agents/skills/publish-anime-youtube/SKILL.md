# 动漫制作与 YouTube 发布

从当前工作区向上定位同时包含 `core/mcp/anime` 和 `.agents/skills` 的项目根目录，不假定用户名、磁盘盘符或检出位置。用户明确调用本技能、要求按此流程制作发布，或明确要求发布时，即授权将指定作品立即公开发布到用户指定账号组的 YouTube；不重复索要发布确认。仅要求下载、找剧或拼接时只生产，不推断发布授权。用户指定预约时，不能调用当前只支持即时公开发布的动漫工具。

## 制作

先读取项目根目录下的 `.agents/skills/produce-anime-video/SKILL.md`，只执行其中的扫描、找剧和必要片段取证，不调用本地拼接入口。标题描述、集数、发布时间和时长优先；必要时比较远程短片段口播；封面识别只作最后兜底。

优先复用最大的不重叠合集。执行清单优先选择完整合集，部分合集只与未覆盖分集组合。全量下载、拼接、分段和上传由 GitHub Action 完成。已存在用户指定的成片时复用，不重新下载生产。保留原始 `manifest.json` 及来源文案，不用发布文案覆盖它们。明确缺集、当前更新范围，不把未完结作品写成“大结局”。集数、时长、拼接方式、原作者和来源只用于选片，以及完成后向用户汇报；不写入标题、描述或标签。

## 转写与文案

1. 确定来源及顺序后，调用 `anime_start_prepare_execution(discovery_path, work_ids, selection_reason)`，用 `anime_poll_task` 轮询完成。它冻结选片清单，仅远程截取第一来源（第一集或合集开头）的前60秒，复用 Groq 转写。短于一分钟时取实际长度，不下载整部作品。返回的 `manifest_path` 是预览清单，只供创作文案和封面，禁止直接发布这条预览。
2. 依据实际转写和原标题里的剧情钩子写文案，不默认全片转写。转写可能有同音错字，可根据上下文校正明显错误；关键剧情不确定时保持悬念，不臆断后续。
3. 标题保留剧名和原标题里的剧情钩子，再写冲突卖点。不写集数、时长，不说明由哪些合集或分集拼成，不出现原作者、来源平台或收录说明。多段原标题不拼接。原标题中的话题不复制进标题。共用标题不超过100字符。
4. 描述前两行突出主角处境、冲突和悬念，随后用自然段展开开场设定、观看理由与关注引导。允许富有想象力的比喻、夸张修辞、设问和宣传口吻；不把未出现的人物、结局、战绩或奖励写成已发生事实。通过“能否”“会如何”等句式营造悬念。描述不写集数、时长、拼接方式、合集来源、原作者、作品收录或来源平台。
5. 描述正文不堆搜索词，不写「搜索关键词」或任何关键词清单。共用描述不超过5000字符。
6. 生成约20—35个去重且相关的 YouTube 搜索标签，兼顾简繁体、常用简称和英文。`tags` 是不带 `#` 的数组，保守总预算为每个标签字符数加3，总和不超过420，预留平台去重标记，且不把这份数组贴进描述。描述底部直接放3—8个最相关话题，每个以 `#` 开头，话题之间用空格分隔。
7. 共用标题、描述及标签在工具调用前向用户简要展示重点；已有发布授权时不等额外确认，继续执行。

## 封面

标题确定后、发布前，调用 `anime_prepare_youtube_thumbnails(manifest_path, titles)`。titles 只传一个共用标题。它只从第一段成片抽一帧作为全片画风参考，并返回宿主生图任务。

对 `needs_generation` 为真的任务，宿主先查看这一张参考帧，再一次生成 16:9 封面。画风必须和参考帧一致。标题原文和画面必须在同一次出图里一起生成，标题放在画面正中间，不要放在顶部或底部。禁止先出无字图再贴字、叠字或后期加字。不改字、不漏字，不另加文字。不要调用千问或其他生图接口代替宿主。

生成后调用 `anime_save_youtube_thumbnails(context_path, images)`。`images` 每项包含 `image_id` 和宿主图片的 `image_path`。全部 `cache_hit` 时传空数组，工具会复用已有封面。

## 发布

封面保存后，调用 `anime_dispatch_github_execution(manifest_path, titles, descriptions, tags, account_group)`；标题和描述数组各只传一个元素，所有分段共用文案和封面。必须从用户指令或部署配置取得账号组，缺失时询问。工具上传执行包和封面到 R2，再启动 main 上的 `publish-anime-youtube.yml`。GitHub 授权使用部署环境的 `ANIME_GITHUB_TOKEN` 或本机已登录的 gh；不把凭据写入执行包。

Action 不调用 LLM、Groq 或生图服务。它从清单中的原始作品链接重新解析临时下载地址，全量下载并核对作品 ID 和时长。单个现成合集保留原文件；多个来源按每段三小时上限均分拼接。随后逐段立即公开上传、设置共用封面、核验平台处理状态和实际时长，并写回 D1。来源失效、时长不符或账号组指向变化时停止，不自行替换来源。

来源、完整成片和上传回执保存到 R2。重跑同一执行 ID 时恢复已持久化的来源与成片，复用上传回执继续核验，按文件摘要和频道查重。拼接尚未全部完成时重跑拼接；未保存的下载需重做。部分成功时保留已发布结果。

返回 `dispatched` 只代表成功触发，不代表视频已发布。向用户交付执行 ID 和工作流链接即可，无需宿主持续在线轮询。用户查询进度时调用 `anime_get_github_execution_result(execution_id)`，以 `succeeded` 结果中的实际链接为准。失败先检查 Action 日志、R2 结果和回执，修复明确原因后重跑同一执行 ID，不生成不同执行包盲目重传。

用户明确指定已有本地完整成片时，可继续使用 `anime_start_transcribe_intro`、封面工具和 `anime_start_publish_youtube`，无需重新下载；主页找剧并发布默认使用上述 Action 流程。

当前会话未加载新增工具时，无需绕过 MCP：使用项目 `ops/anime/run_mcp_tool.py` 通过 MCP stdio 调用新工具。先将工具参数写到 `cache/output/anime/` 下的 JSON 文件，然后在项目根目录用 Docker 运行该脚本，传 `--tool`、`--arguments-file` 和 `--result-file`。容器需挂载项目到 `/app`，另显式挂载项目 `cache` 到 `/app/cache`（镜像声明的卷会遮住缓存）；注入项目 `.env`，工作目录 `/app`。宿主 Windows 产物路径由工具映射到 Docker 挂载路径。需要网络代理时复用项目已配置的代理，不输出密钥。

Docker 触发 Action 时还需注入 `ANIME_GITHUB_TOKEN` 或 `GH_TOKEN`。本机已有 gh 登录时，可在 PowerShell 中把 `gh auth token` 的输出赋给进程环境变量 `GH_TOKEN`，用 Docker 的 `-e GH_TOKEN` 传入，结束后清除该进程变量；禁止把令牌打印、写入参数文件或提交到 Git。

Action 完成后交付 YouTube 链接、实际标题、频道和收录范围；触发阶段明确说明仍在后台执行。凭据不写入技能或 Git，不触发其他平台发布。
