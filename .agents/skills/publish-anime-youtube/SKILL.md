# 动漫制作与 YouTube 发布

从当前工作区向上定位同时包含 `core/mcp/anime` 和 `.agents/skills` 的项目根目录，不假定用户名、磁盘盘符或检出位置。用户明确调用本技能、要求按此流程制作发布，或明确要求发布时，即授权将指定作品立即公开发布到用户指定账号组的 YouTube；不重复索要发布确认。仅要求下载、找剧或拼接时只生产，不推断发布授权。用户指定预约时，不能调用当前只支持即时公开发布的动漫工具。

## 制作

先读取项目根目录下的 `.agents/skills/produce-anime-video/SKILL.md`，通过 anime MCP 扫描主页、自主找剧与排序。标题描述、集数、发布时间和时长优先；必要时比较片段口播；封面只作最后兜底。

优先复用最大的不重叠合集。完整合集直接下载；部分合集只与未覆盖分集拼接。已存在用户指定的成片时复用，不重新下载生产。保留原始 `manifest.json` 及来源文案，不用发布文案覆盖它们。明确缺集、当前更新范围，不把未完结作品写成“大结局”。集数、时长、拼接方式、原作者和来源只用于选片，以及完成后向用户汇报；不写入标题、描述或标签。

## 转写与文案

1. 调用 `anime_start_transcribe_intro(manifest_path)`，用 `anime_poll_task` 轮询完成。它从每段成片零秒开始抽取前60秒，复用项目 Groq 转写。短于一分钟时转写实际长度。原始结果保存在成片旁的 `youtube-intro-序号.json`。
2. 依据实际转写和原标题里的剧情钩子写文案，不默认全片转写。转写可能有同音错字，可根据上下文校正明显错误；关键剧情不确定时保持悬念，不臆断后续。
3. 标题保留剧名和原标题里的剧情钩子，再写冲突卖点。不写集数、时长，不说明由哪些合集或分集拼成，不出现原作者、来源平台或收录说明。多段原标题不拼接。原标题中的话题不复制进标题。每段独立标题不超过100字符。
4. 描述前两行突出主角处境、冲突和悬念，随后用自然段展开开场设定、观看理由与关注引导。允许富有想象力的比喻、夸张修辞、设问和宣传口吻；不把未出现的人物、结局、战绩或奖励写成已发生事实。通过“能否”“会如何”等句式营造悬念。描述不写集数、时长、拼接方式、合集来源、原作者、作品收录或来源平台。
5. 描述正文不堆搜索词，不写「搜索关键词」或任何关键词清单。每段描述不超过5000字符。
6. 生成约20—35个去重且相关的 YouTube 搜索标签，兼顾简繁体、常用简称和英文。`tags` 是不带 `#` 的数组，保守总预算为每个标签字符数加3，总和不超过420，预留平台去重标记，且不把这份数组贴进描述。描述底部直接放3—8个最相关话题，每个以 `#` 开头，话题之间用空格分隔。
7. 每段的标题、描述及共用标签在工具调用前向用户简要展示重点；已有发布授权时不等额外确认，继续执行。

## 封面

标题确定后、发布前，调用 `anime_prepare_youtube_thumbnails(manifest_path, titles)`。它只从成片随便抽一帧作为全片画风参考，并返回宿主生图任务。

对 `needs_generation` 为真的任务，宿主先查看这一张参考帧，再一次生成 16:9 封面。画风必须和参考帧一致。标题原文和画面必须在同一次出图里一起生成，禁止先出无字图再贴字、叠字或后期加字。不改字、不漏字，不另加文字。不要调用千问或其他生图接口代替宿主。

生成后调用 `anime_save_youtube_thumbnails(context_path, images)`。`images` 每项包含 `image_id` 和宿主图片的 `image_path`。全部 `cache_hit` 时传空数组，工具会复用已有封面。

## 发布

封面保存后，调用 `anime_start_publish_youtube(manifest_path, titles, descriptions, tags, account_group)`；标题和描述数组与清单分段一一对应。必须从用户指令或部署配置取得 `account_group`，缺失时询问，不写死账号组、频道名、频道 ID 或凭据引用。工具只发布到该数据库账号组的 YouTube 频道，核验授权身份，逐段立即公开发布，并上传宿主已保存的封面。没有对应封面时拒绝发布。

轮询 `anime_poll_task` 至完成，未结束禁止再次 start。工具以成片 SHA-256 和频道身份查询 D1 `publication_records` 去重，并复用 media-publisher 的官方 YouTube 发布接口。每段平台成功后先存本地回执，再逐条写回数据库；部分失败时保留已成功结果。失败先检查任务错误、本地回执与数据库记录，不盲目重新上传；修复明确可恢复的原因后重试最多一次，仍失败则报告。

当前会话未加载新增工具时，无需绕过 MCP：使用项目 `ops/anime/run_mcp_tool.py` 通过 MCP stdio 调用新工具。先将工具参数写到 `cache/output/anime/` 下的 JSON 文件，然后在项目根目录用 Docker 运行该脚本，传 `--tool`、`--arguments-file` 和 `--result-file`。容器需挂载项目到 `/app`，另显式挂载项目 `cache` 到 `/app/cache`（镜像声明的卷会遮住缓存）；注入项目 `.env`，工作目录 `/app`。宿主 Windows 产物路径由工具映射到 Docker 挂载路径。需要网络代理时复用项目已配置的代理，不输出密钥。

成功后交付 YouTube 链接、实际标题、频道、集数范围和本地文案路径；不得仅凭上传开始就宣称发布成功。凭据不写入技能或 Git，不触发其他平台发布。
