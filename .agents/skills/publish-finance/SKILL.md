# 发布财经视频

使用 `publishing` MCP，业务线与内容类型均为 `finance`。产物查找、R2 恢复、去重、账号路由、平台预约和记录写入由 MCP 负责，不直接运行发布脚本。

## 用户信息与默认时间

- 必须明确产物计划发布日期 `publish_date` 和账号组；缺少时追问。日期用于选择产物，与实际预约时间分开。
- 先调用 `publishing_list_account_groups`，传 `business_line="finance"`、`account_group="finance"`；指定平台时同时传 `platforms`，只检查本次使用的账号。只有真实页面检测 `status="connected"` 才可报告有效，不用 Cookie 或声明的有效期推断。财经成片的账号组名称是 `finance`。
- 用户未指定平台时，检查并使用所选账号组全部启用的平台；指定时只用指定平台。登录失效的目标账号需要用户登录，不能自动排除。
- 明确说“立即/现在”时立即发布。未给具体时间时，不传 `publish_mode`、`publish_at`，由公共发布层按计划发布日期北京时间 14:00、18:00 各安排一篇。
- 两篇齐全时第一篇排 14:00、第二篇排 18:00；只有一篇时排 18:00。当天 14:00 已过时，只安排 18:00 一篇，不把两篇挤到同一时段。仅明确指定 18:00 时也只安排一篇，优先第二篇。
- 两个时段都已过时，追问立即发布还是改约未来时间，不自动补发。明确指定其他时间时遵从用户要求，该时段只安排一篇。

## 头条预约窗口限制

- 头条官方预约是**滚动 7 天窗口**：第 1～6 天整点可选，最远第 7 天只开放到 17:00，18:00 天然没有选项。这是平台限制，不是缺陷，不要反复重试也不要当成故障排查。
- 计划发布日期正好落在头条可选范围的最远一天时，第二篇主动避开 18:00，改排该天最晚可用时段（默认 17:00）；第一篇 14:00 保持不变。
- 兜底规则：头条任务返回「小时未找到选项」一类错误时，直接把预约时间改到该天**最晚可选小时**重发这一条（只重发这一条），不换日期、不跳过、不向用户报成 bug。日期正确即视为成功。

## 执行与交付

1. 先调用 `publishing_list_account_groups` 检查所有本次目标账号。有账号需要登录或检测失败时立即提示，展示可用的二维码或授权入口，处理完成后重新预检；账号未全部通过前不读取、恢复或上传成片。只有 `all_accounts_ready=true` 时，先向用户用醒目粗体发送“**全部账号已登录，开始发布**”，再自动继续，无需用户确认。随后调用 `publishing_preview`。没有可发布内容时说明原因并停止。
   用户指定单条标题时，从预检结果匹配对应 `production_id`，再次预检及实际发布均传入该标识，只发布这一条。
2. 根据上述时间规则调用 `publishing_start_publish`，用 `publishing_poll_task` 轮询同一任务至完成；传回 `after_revision` 并设置 `wait_seconds=25`，无变化时由程序等待，不反复把完整任务送给模型。客户端超时不重复启动。
3. 账号 `status="login_required"` 时先让用户登录，不继续恢复成片或发布；`status="error"` 是检测失败，排查页面或网络，不宣称账号过期。抖音、快手、头条或视频号明确需要扫码时，调用登录工具并把 `qr_path` 直接展示为 Markdown 图片及可点击文件链接；轮询扫码成功后刷新账号状态并重新预检。
4. 展示逐平台成功、预约或失败结果，不重复手工入库。不接受应用内定时队列代替平台官方预约。

## 观察耗时与费用

- 用户指定首日结束停下时，只启动首日任务；完成或部分失败后均停止，不自动补发、不启动后续日期。
- 同一批账号通过后不额外再调用一遍账号列表；后续预检和上传保留各自的真实会话校验。
- 下载验证使用 `local_video_path(record)` 定位每个分片的实际目录，复用已下载文件，不把第二篇放进第一篇目录。
- 完整调用结果写入本地观察记录，模型默认只读摘要和状态变化；失败时再读取对应项明细。
- 多步骤执行优先保持同一个 MCP SDK 会话。程序负责轮询、去重和完整日志，向模型只输出账号异常、预检计数、变化后的进度及最终成功失败汇总；等待同一会话时按约 45 秒读取一次终端，不高频读取空输出。
- 记录预检分阶段耗时、各平台各成片耗时、工具调用次数和返回文本量。没有实际用量账单时，不把文本量写成精确 token 或金额。
