# 发布财经视频

使用 `publishing` MCP，业务线与内容类型均为 `finance`。产物查找、R2 恢复、去重、账号路由、平台预约和记录写入由 MCP 负责，不直接运行发布脚本。

## 用户信息与默认时间

- 必须明确产物计划发布日期 `publish_date` 和账号组；缺少时追问。日期用于选择产物，与实际预约时间分开。
- 先调用 `publishing_list_account_groups` 核实账号，不猜账号路由。财经成片的账号组名称是 `finance`。
- 用户未指定平台时，使用所选账号组全部启用且当前可用的平台；指定时只用指定平台。
- 明确说“立即/现在”时立即发布。未给具体时间时，不传 `publish_mode`、`publish_at`，由公共发布层按计划发布日期北京时间 14:00、18:00 各安排一篇。
- 两篇齐全时第一篇排 14:00、第二篇排 18:00；只有一篇时排 18:00。当天 14:00 已过时，只安排 18:00 一篇，不把两篇挤到同一时段。仅明确指定 18:00 时也只安排一篇，优先第二篇。
- 两个时段都已过时，追问立即发布还是改约未来时间，不自动补发。明确指定其他时间时遵从用户要求，该时段只安排一篇。

## 执行与交付

1. 核实账号组与平台，调用 `publishing_preview`。没有可发布内容时说明原因并停止。
   用户指定单条标题时，从预检结果匹配对应 `production_id`，再次预检及实际发布均传入该标识，只发布这一条。
   YouTube 优先直接上传本地成片，不先交付 R2；本地缺失时才从已有 R2 恢复。封面使用制作时保存的 `cover.png` 原图，只有原图缺失时才截取成片第一帧，并通过 YouTube API 上传独立缩略图。
2. 根据上述时间规则调用 `publishing_start_publish`，用 `publishing_poll_task` 每 15～30 秒轮询同一任务至完成；客户端超时不重复启动。
3. 登录检测失败时按 MCP 返回值恢复。抖音、快手、头条或视频号需要扫码时，调用登录工具并把 `qr_path` 直接展示为 Markdown 图片及可点击文件链接；轮询扫码成功后刷新账号状态并重新预检。
4. 展示逐平台成功、预约或失败结果，不重复手工入库。不接受应用内定时队列代替平台官方预约。
