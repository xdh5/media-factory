# 长视频拆分并发布 YouTube

从当前工作区向上定位同时包含 `core/mcp/anime` 和 `.agents/skills` 的项目根目录，不假定用户名、磁盘盘符或检出位置。用户给出长视频链接并要求发布，即授权把该作品公开发布到指定动漫账号组的 YouTube，不重复索要发布确认。

**这些视频非常大，宿主禁止下载完整视频。** 文案只能来自链接解析出的原标题、描述、话题，以及工具远程截取的第一分钟转写。全量下载、拆分和上传全部由 GitHub Action 在 Runner 上完成。

## 作品分组

一条链接通常就是一部完整作品，单独走一遍流程：一个执行包、一个以作品名命名的播放列表。用户给出多条不同作品的链接时，逐条执行，各自进入各自的合集。多条链接明显属于同一作品（上部/下部、分卷合集）时，放在一次执行里按给出顺序拼接，再按时间线统一拆分。

## 配置预检

先调用 `anime_get_production_config`，自动取得 `ANIME_ACCOUNT_GROUP` 或数据库中唯一启用的动漫 YouTube 账号组。用户明确指定的账号组优先。已有唯一可用组直接复用，不要求用户重复提供。

## 冻结清单

1. 调用 `anime_start_prepare_split_execution(share_texts, series_name, selection_reason)`。
   - `share_texts`：数组，每个元素一条分享口令或链接，顺序与播放顺序一致。
   - `series_name`：作品名，同时是 YouTube 播放列表名。从原标题描述里提炼剧名，不要带集数和平台信息。
   - `selection_reason`：必须说明来源顺序、这是完整长视频以及**已完结**，不含“已完结”会被拒绝。
2. 用返回的 `task_path` 调用 `anime_poll_task` 到 `done=true`。两次轮询至少间隔 5 秒。
3. 成功后取得 `manifest_path`、`split_plan`（总时长、段数、每段区间）和每条来源的原标题、描述、话题。工具已远程读取第一来源开头 60 秒并转写，转写结果在 `intros` 里。

## 文案

依据来源描述和开头转写编写剧情向文案。允许合理想象、夸张修辞、设问和悬念口吻；不把未出现的人物、结局、战绩或奖励写成已发生事实，关键剧情不确定时保持悬念。不写来源平台、原作者、时长、拆分方式或收录说明。

1. 共用标题先写剧名和剧情钩子，再写冲突卖点，最后追加包含“已完结”的关键词后缀，关键词不得前置。标题不超过 80 字符，为 Action 自动追加 `第N集（共M集）` 预留长度。多段原标题不拼接，原标题里的话题不复制进标题。
2. 描述前两行突出主角处境、冲突和悬念，随后用自然段展开开场设定、观看理由与关注引导。描述不写集数、时长、拆分方式、原作者或来源平台。共用描述不超过 5000 字符。
3. 描述正文不堆搜索词，不写关键词清单。底部直接放 3—8 个最相关话题，以 `#` 开头、空格分隔。
4. 生成约 20—35 个去重且相关的搜索标签，兼顾简繁体、常用简称和英文。`tags` 是不带 `#` 的数组，字符数加 3 的总和不超过 420。不要把这份数组贴进描述。
5. 标题、描述、搜索标签和底部 hashtag 都必须包含“已完结”；描述底部 hashtag 必须包含 `#已完结 #一口气看完 #完整全集 #超长合集 #爽文`。长度和剧情类型不适用时不用“超长合集”或“爽文”，不为关键词虚构事实。生成后分别检查四处，“已完结”不得缺失。

## 封面

调用 `anime_prepare_youtube_thumbnails(manifest_path, titles)`，`titles` 只传一个共用标题。工具按 `split_plan` 的段数返回独立宿主生图任务，每张标题自动包含 `第N集（共M集）`。

对每个 `needs_generation` 为真的任务，宿主先查看共用参考帧，再分别生成一张 16:9 封面。各集画面可以不同，画风必须和参考帧一致。标题原文（含集数）和画面必须在同一次出图里一起生成，标题放在画面正中间，禁止先出无字图再贴字、叠字或后期加字。不改字、不漏字、不另加文字。不要调用千问或其他生图接口代替宿主。

生成后调用 `anime_save_youtube_thumbnails(context_path, images)`，`images` 每项包含 `image_id` 和宿主图片的 `image_path`。全部 `cache_hit` 时传空数组。

## 发布

封面保存后，调用 `anime_dispatch_github_execution(manifest_path, titles, descriptions, tags, account_group)`；标题和描述数组各只传一个元素，Action 为多段自动追加集数并使用对应分段封面。账号组省略时工具自动解析。

工具上传执行包和全部封面到 R2，启动 main 上的 `publish-anime-youtube.yml`。Action 全量下载来源并核对时长，按时间线均分成每段不超过三小时，逐段上传、设置封面、加入 `series_name` 播放列表，全部上传完成并保存回执后写回 D1 成功退出，不等待 YouTube 服务端转码。关键帧无损裁切优先，偏差过大才转码该段。

返回 `dispatched` 只代表成功触发。向用户交付执行 ID 和工作流链接即可。查询进度调用 `anime_get_github_execution_result(execution_id)`，以 `succeeded` 结果中的实际链接为准。上传完成与转码完成分别报告，不声称已验证转码成功。失败先检查 Action 日志、R2 结果和回执，修复明确原因后重跑同一执行 ID。

## 兜底与故障

当前会话未加载新增工具时，无需绕过 MCP：使用项目 `ops/anime/run_mcp_tool.py` 通过 MCP stdio 调用新工具。先将工具参数写到 `cache/output/anime/` 下的 JSON 文件，然后在项目根目录用 Docker 运行该脚本，传 `--tool`、`--arguments-file` 和 `--result-file`。容器需挂载项目到 `/app`，另显式挂载项目 `cache` 到 `/app/cache`（镜像声明的卷会遮住缓存）；注入项目 `.env`，工作目录 `/app`。需要网络代理时复用项目已配置的代理，不输出密钥。Docker 触发 Action 时还需注入 `ANIME_GITHUB_TOKEN` 或 `GH_TOKEN`；本机已有 gh 登录时可把 `gh auth token` 的输出赋给进程环境变量再用 `-e GH_TOKEN` 传入，结束后清除，禁止把令牌打印、写入参数文件或提交到 Git。

链接解析失败、远程时长探测失败或来源失效时报告具体错误并停止，不得改为本地全量下载。凭据不写入技能或 Git，不触发其他平台发布。
